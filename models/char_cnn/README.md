# CharCNN — Graphito stylometric channel (Channel B)

A character-level CNN that estimates whether a C/C++ submission was generated by an LLM. It
produces `prob_sintetico` (scalar) and a 1024-d authorship embedding that the bimodal fusion
(`models/fusion.py`) combines with GraphCodeBERT. The teacher makes the final call.

Two versions coexist. The deployed `best_model.pth` is still a **v1 (legacy)** checkpoint; the
**v2** pipeline in `models/char_cnn/v2/` is the reproducible replacement. The inference facade
serves both and picks the path from the checkpoint's version fields.

## Architectures

| | v1 (legacy, frozen) | v2 (`ARCH_VERSION = 2`) |
|---|---|---|
| Code | `model.py` (`CharCNN` / `MultiScaleCharCNN`), `config.py` | `v2/model.py` (`CharCNNV2`), `v2/config.py` |
| Embedding | 128-d over the legacy alphabet | 128-d, PAD (0) embedding masked |
| Convolutions | kernels 3/5/7/9 x 64 filters + `BatchNorm1d` | kernels 3/5/7/9 x 64 filters + channel `LayerNorm`, masked |
| Pooling | global max + avg (includes padding) | masked max + mean over real positions only |
| Head | FC 1024 + BatchNorm + dropout, FC 2 | FC 1024 (embedding), one dropout 0.4, FC 2 |
| Input | one fixed window (`seq_length`, 4096) | windows of 4096, stride 2048, at most 8 (`linspace` starts beyond the cap); logits averaged |
| Properties | output depends on padding and batch | padding- and batch-invariant (tested to 1e-5), no BatchNorm |

v1 code (`preprocess.py`, `model.py`, `dataset.py`, `config.py`) is frozen: it only serves
legacy checkpoints and is never edited.

## Preprocessing v2 (`v2/preprocess.py`, `PREPROC_VERSION = 2`)

The same symmetric steps run on human and AI files, without looking at the label:

1. CRLF/CR to LF; drop C0 controls (except tab/LF), DEL, zero-width characters, BOM and U+FFFD.
2. Fold quotes, dashes, spaces and diacritics to ASCII (`Zadaća` -> `Zadaca`); drop any other
   non-ASCII character.
3. Strip comments with `models.evaluation.normalize.strip_comments` (C++14 digit separators are
   shielded first).
4. Remove course headers and markers (`Zadaca`, `Zadatak`, `Tutorijal` header lines, print
   lines carrying them, leftover marker tokens).
5. Line-preserving canonical whitespace (tabs to spaces, runs collapsed outside literals, empty
   lines dropped).

The output is pure `ALPHABET` (LF + printable ASCII): PAD = 0, UNK = 1, character `c` ->
`char_index(c)`. Files with fewer than 60 non-whitespace normalized characters are abstained on
at inference (`abstained: true`, `score: None`). Before training, a **leak guard** fails the run
(exit 2) when more than 0.1% of the normalized human representatives still contain non-alphabet
characters or course markers (`autotest` is detected, not stripped).

## Inference

```python
from models.char_cnn.inference import CharCNNInference

engine = CharCNNInference("models/char_cnn/best_model.pth")   # or a v2 run's best.pth
result = engine.predict_text("int main() { ... }")
```

Every result has the legacy keys (`prediction`, `class_id`, `confidence`, `prob_humano`,
`prob_sintetico`, `ai_probability`, `embedding`, `insufficient_length`) plus `score`,
`abstained`, `n_windows`, `preproc_version` and `arch_version`. Checkpoints without version
fields run the legacy path unchanged; `arch_version == preproc_version == 2` runs v2; any other
combination raises `ValueError`. v2 scores are raw (uncalibrated); the run's `calibration.json`
holds the val-fitted Platt calibration.

## Command-line tools

All commands run from the repository root. None of them writes `models/char_cnn/best_model.pth`
except `promote`.

| Command | Purpose |
|---|---|
| `python -m models.char_cnn.v2.train [--device cuda] [--seed 42]` | Train v2 on `split_v1`, select by val ROC-AUC, calibrate on val, evaluate test once |
| `python -m models.char_cnn.v2.evaluate --run-dir runs/char_cnn/<ts> [--force]` | Re-run calibration and the test evaluation from an existing `best.pth` |
| `python -m models.char_cnn.v2.baseline [--checkpoint models/char_cnn/best_model.pth]` | Score a legacy checkpoint on the same test views (labelled contaminated) |
| `python -m models.char_cnn.v2.promote runs/char_cnn/<ts>/best.pth [--target ...] [--force] [--dry-run]` | Copy an evaluated v2 checkpoint onto the deployed path |
| `python -m models.char_cnn.train ...` | Legacy entry point; delegates to `models.char_cnn.v2.train` |

**Train** flags: `--manifest` (default `data/splits/split_v1.json.gz`), `--expected-sha256`,
`--root`, `--runs-root runs`, `--seed 42`, `--device`, `--epochs 50`, `--batch-size 128`,
`--lr 1e-3`, `--weight-decay 1e-4`, `--early-stop 7`, `--lr-patience 3`, `--lr-factor 0.5`,
`--eval-batch-size 32`, `--n-boot 1000`, `--limit-per-class N` (debug only, recorded),
`--model-config <json>` (`CharCNNV2Config` overrides). Invalid numbers are rejected before
anything is written. `config.json` records `status`, `failure` and `best_sha256` (the selected
checkpoint); an interrupt also marks the run failed before propagating.

Exit codes (shared by every v2 CLI, `models/char_cnn/v2/runs.py`):

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | refused; nothing written (or the run left unchanged) |
| 2 | train: leak guard failed (run marked failed); also argparse usage errors |
| 3 | the run's `config.json` is marked `failed` (stage and reason recorded) |
| 4 | a write failed part-way; the previous files and status were restored |

**Evaluate** refuses (exit 1) a run whose status is not `complete` or `failed` during
`evaluate` (a `running` run is never touched), a `best.pth` that differs from `best_sha256`, a
run that already has `calibration.json`/`metrics.json` unless `--force`, and a run whose manifest
or data cannot be loaded. It snapshots the run first: if the evaluation fails, the previous
outputs are restored (a `complete` run stays complete, exit 4; a failed run stays failed, exit 3).
It reuses the run's manifest, data root, seed, `--n-boot` and `--limit-per-class` (`--manifest`,
`--root`, `--n-boot`, `--batch-size`, `--device` override them).

**Baseline** flags: `--checkpoint`, `--manifest`, `--expected-sha256`, `--root`,
`--runs-root runs`, `--device`, `--seed 42`, `--n-boot 1000`. It refuses non-legacy checkpoints,
hashes the checkpoint before and after (a change fails the run), and is never calibrated: its
only operating point is `argmax_0.5` with `source: "manual"`. The legacy `CharCNNConfig` creates
`models/char_cnn/{weights,logs}/` relative to the working directory (both gitignored).

**Promote** requires a v2 checkpoint that is its run's `best.pth`, matches the run's
`best_sha256`, and whose run is `complete` with `metrics.json` and `calibration.json`. It refuses
when `git status --porcelain --ignored -- <target>` reports any entry (modified, staged,
untracked, or ignored unless tracked and identical to `HEAD`) or git fails, unless `--force`.
The source bytes are read once and re-hashed before writing; the sidecar
`best_model.provenance.json` (run id, source/target/previous/config/calibration sha256, headline
AUCs, forced flag) is staged before the target is replaced, and a failed write restores the
previous target and sidecar (exit 4). `--dry-run` runs every check and writes nothing.
Promotion is a user decision; no other tool calls it.

## Run layout

```
runs/char_cnn/<ts>/                 # v2 training run
  config.json        provenance, model config, hyperparams, status, leak_guard, sampling, selection, calibration ref
  leak_guard.json    shares per pattern and class; offending ids on failure
  history.csv        epoch, train_loss, val_roc_auc, val_pr_auc, lr, n_epoch_samples, seconds
  best.pth           selected checkpoint (weights_only-loadable, embeds its full config)
  calibration.json   Platt calibration fitted on val representatives only
  metrics.json       headline: test representatives, CI95 by dup_group, per group, per generator, n_abstained
  report.md          the same in Markdown, plus the shortcut audit
  shortcuts.json     residual formatting shortcuts per class (raw and normalized), report-only
  scores_val.csv, scores_test.csv, roc/pr/reliability CSVs and plots
  test_all/          secondary view: every non-broken test file
runs/char_cnn_legacy/<ts>/          # legacy baseline (contaminated: true), same views, no calibration
```

`runs/` is gitignored; selected reports are committed explicitly.

## Deprecations

- `data/train_charcnn.py` (proof of concept) was removed.
- `prepare_dataset.py` and `dataset_manifest.json` are deprecated in favour of the `split_v1`
  manifest; importing `prepare_dataset` emits a `DeprecationWarning`. They stay until the legacy
  tests migrate.
- `train.py` keeps only `compute_metrics`, `evaluate` and `train_epoch` (imported by
  `scripts/generate_tt_figures.py` and the legacy tests); its `main` delegates to the v2 trainer.

## Results

Reports are committed under `runs/char_cnn/20261011-015734/` (v2) and
`runs/char_cnn_legacy/20261011-033124/` (legacy baseline); weights and score CSVs are not committed.

**v2 run** (`split_v1` sha256 `e835362d…`, seed 42, CUDA, RTX 2060 SUPER). The leak guard passed:
0.0056% of normalized human representatives still match a course marker (threshold 0.1%), 0% are
outside the alphabet. Training used 874 AI + 874 freshly drawn human files per epoch (~6 s/epoch);
model selection picked epoch 30 of 38 (early stop) by val ROC-AUC 0.9991 / PR-AUC 0.9890.
Calibration (Platt) and thresholds were fitted on val only (2,868 human / 209 AI); test was scored
once.

| Test view | n (AI) | ROC-AUC [CI95] | PR-AUC [CI95] | ECE |
|---|---|---|---|---|
| Representatives (headline) | 4,531 (330) | 0.994 [0.991, 0.996] | 0.958 [0.944, 0.973] | 0.009 |
| All files (secondary) | 9,649 (331) | 0.993 [0.990, 0.997] | 0.938 [0.919, 0.959] | 0.004 |

Operating points on the headline view (thresholds from val, observed prevalence 7.3% AI):

| Target FPR | Achieved FPR | Recall | Precision |
|---|---|---|---|
| 1% | 0.95% [0.69, 1.28] | 0.888 [0.858, 0.922] | 0.880 [0.840, 0.912] |
| 5% | 4.57% [3.97, 5.18] | 0.973 [0.956, 0.989] | 0.626 [0.583, 0.669] |

On the all-files view (duplicates included, observed prevalence 3.4% AI) the same val-fitted
thresholds do **not** keep their targets everywhere: the 1% threshold gives FPR 0.93% [0.61, 1.30],
recall 0.888, precision 0.772, but the 5% threshold gives FPR 9.28% [4.14, 14.58], recall 0.973,
precision 0.271. The cause was not analysed here; plausible candidates are duplicate-heavy human
groups (template or copied solutions counted many times) and very short human files that the
deployment API would abstain on but this evaluation scores. Any operational threshold must be
re-validated on the deployment population (SDD-4).

Run provenance: `config.json` records absolute local paths and `dirty: true`; the only uncommitted
change at run time was the user's local `models/char_cnn/best_model.pth`, which the v2 run does not
read. The manifest and calibration are identified by their sha256.

CIs are bootstrap CI95 resampled by duplicate group. Per generator (each AI group vs all test
humans): deepseek-chat n=227, ROC-AUC 0.992, recall@1%FPR 0.88; qwen3 n=100, ROC-AUC 0.997,
recall@1%FPR 0.90; every other generator has 0–1 test files and is `low_support`.

**How to read these numbers.** They are honest for this corpus but they are *not* evidence of a
general "AI style" detector:

- Residual shortcuts after normalization (`shortcuts.json`, test): `std::` appears in 46% of human
  vs 24% of AI files; `using namespace` in 7% of human vs 30% of AI files; AI files are shorter
  (42% are 1–2 KB vs 24% of humans; 3% are ≥ 4 KB vs 13.5%). These course conventions and length
  differences are learnable without any notion of authorship by an LLM.
- 99% of AI test files come from two generators (deepseek-chat, qwen3) prompted with the same six
  profiles; results do not transfer to unseen generators or to edited AI output (Phase 2:
  leave-one-LLM-out, matched regeneration, TF-IDF probe).

**Legacy baseline** (current `models/char_cnn/best_model.pth`, sha256 `d3692747…`, byte-identical
before and after): headline ROC-AUC 0.999 [0.998, 1.000], PR-AUC 0.993, argmax@0.5 recall 0.967 at
FPR 0.26%. It is labelled `contaminated`: the checkpoint was trained on the legacy subproblem split,
which overlaps `split_v1` test, and it uses v1 preprocessing (course headers, CR and control
characters visible). These numbers are not comparable with v2, and neither is the old 96% claim.

**Promotion.** No checkpoint was promoted; `best_model.pth` is unchanged. Promoting the v2 model
(and recalibrating the backend's `THRESHOLD_AI`) is a decision for SDD-4.

## Limitations

- Domain shift: the human corpus is Bosnian-course C/C++, while deployment targets Spanish-speaking
  courses; course markers and language are normalized away, but topic and style may still differ.
- One generator dominates the AI files, so per-generator results for the others are low-support.
- AI files are few compared with human files: AUC confidence intervals are wide and groups with
  fewer than 30 files of either class are flagged `low_support`.
- The split unit is the assignment block, not the student, so a student's style can appear in
  train and test.
